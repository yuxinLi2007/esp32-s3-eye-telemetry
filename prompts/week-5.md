# 第 5 周任务：接通按键说话与语音播报

> 本周在第 4 周自然语言助手之上接通语音链路：按键式（半双工）录音 → 识别 → 任务执行 → 语音播放。
> 运行位置必须可区分：设备音频未就绪时可用电脑音频（浏览器麦克风），但要在界面上如实标注。

## 一、本周目标（课程第 5 周）

从"说一句话"到"听到回答"，把每个环节做成**可观察的状态**：
录音 → 识别（ASR，产出文本任务）→ 任务执行（复用第 4 周查询/采集处理）→ 语音播放（TTS）。
用同一句任务对照文字与语音两个入口。

## 二、功能要求（验收点）

1. **按键式录音/停止（半双工）**：按下开始录音、再按停止结束，得到一段音频并送识别。
   录音期间界面处于"录音中"状态，只有停止后才进入下一环节。
2. **识别 → 文本任务**：ASR 产出的文本进入第 4 周的自然语言处理（查询/采集/澄清全都复用），
   不另写一套任务逻辑。
3. **任务执行状态可观察**：识别成功后按第 4 周口径执行（查询直答；采集走指令通道并轮询），
   执行结果照实呈现，无完成证据不得说"已采集成功"。
4. **语音播放（TTS）**：把最终回答合成语音并播放；播放期间有"播放中"状态。
5. **四种状态 + 运行位置**：录音中 / 识别中 / 执行中 / 播放中是四个可观察状态，
   用色点或极简图标表示（单强调色红 + 中性），**不加说明文字**；
   界面标注音频来源与运行位置（如"电脑音频·浏览器"vs"设备音频"），来源不同必须可区分。
6. **异常可理解**：无声、识别失败、服务超时都必须产生明确反馈（如"识别失败：无有效语音"），
   文字入口保持可用（不能被语音功能堵死）。

## 三、本仓库上下文（必须遵守的既有事实）

- 复用第 4 周接口路径与口径（不改路径、不改轮询间隔、不删 ui_check 断言的 DOM 与函数）。
- 新增语音接口可加新路径（如 `/api/v1/voice/transcribe`、`/api/v1/voice/speak`），
  鉴权口径与现有指令一致（语音服务密钥只存服务端环境变量）。
- ASR/TTS 用授权服务并通过环境变量配置（如 `VOICE_ASR_URL / VOICE_TTS_URL / VOICE_API_KEY / VOICE_MODEL`）；
  未配置或调用失败时状态如实呈现"识别失败/合成失败"，不允许假装成功。
- 轮询仍为 2s；`ui_check.mjs` 是第一道门槛（第 4 周的断言全部保留）。
- 浏览器录音（MediaRecorder/Web Audio）仅在用户按下按键时启用，页面加载时不请求麦克风权限。

## 四、UI 约束（必须逐条满足）

- 单文件页面，无构建、无 CDN；`commands.js` 保留拆分，语音 / 助手逻辑内联进 index.html。
- 不改 API 路径与轮询间隔；不删除或重命名 ui_check.mjs 断言的 DOM。
- 页面只留在第 4 周精简版基础上，**指令输入区新增按键式录音/停止按钮与四态指示**：
  报警条（仅异常时出现）、实时曲线（缺口红色竖带）、三项指标卡、采集开关、指令输入区（NL 输入 + 录音/停止 + 四态色点）。
- 状态只用色点或极简图标表达，不加说明文字；运行位置（电脑音频/设备音频）用不显眼的最小标注区分即可。
- 底色白或极浅灰；单强调色红；无边框/阴影/分隔线；圆角 ≤6px；不用渐变与 emoji；窄屏不横向滚动。

## 五、护栏

- 不直接推 main，只在 `week-5-redo` 分支上提交（从合并了第 4 周的 main 出发）；不自动合并。
- 一次只做这一周，不夹带第 6 周及以后的改动。
- 失败即停：ui_check 不过就停，保留日志，不开 PR。
- 音频数据最小化：只在用户主动录音时采集，不持续监听；密钥与音频样本不入库、不入仓库。

## 六、完成定义（DoD）

1. 服务端语音接口（转写 + 合成）可用，未配置/超时/无语音都有明确错误码与状态；
   `pytest server/test_voice.py` 全绿。
2. 第 4 周助手测试与既有测试不回归（`test_assistant.py / test_ingest.py / test_commands.py` 全绿）。
3. `node tools/ui_check.mjs` 通过（起服 + seed 预置数据）。
4. 界面为白底精简版；按键录音→识别→执行→播放四态可观察、可区分，音频来源（运行位置）有标注；
   文字入口仍可用。
5. 提交内容只涉及第 5 周功能；提交信息用现有风格前缀。

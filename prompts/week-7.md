# 第 7 周任务：按需获取一张环境图像

> 本周在既有任务与存储服务之上，增加"按需环境快照"（on-demand image capture）：
> 用户请求查看环境时，系统只取一张图，并必须说清采集是否成功、采到的是哪一时刻的画面。
> 前 2 学时做大方向（请求-图像-时间关联），后 2 学时做反馈状态与保留策略。

## 本周问题

用户请求查看环境时，系统如何说明采集是否成功，采到的是哪一时刻的画面？

## 本周目标

- **按需图像采集**：在既有任务通道（commands）与存储服务中增加按需图像采集；
  复用摄像头驱动或实际图像接口；**只在请求或教学事件触发后取图**，不做持续取图/录像。
- **授权与输入有效性**：图像采集与"能改设备行为"的操作同级鉴权（沿用 CONTROL_TOKEN
  口径）；图像输入与有效性要说明清楚——镜头遮挡 / 画面不可用 / 采集失败各有明确状态。
- **请求-图像-时间关联**：一张图像记录三样东西：发起请求（request_id）、图像记录、
  采集时间（服务端接收时刻 + 设备声称的采集时刻），可反查"这张图是哪次请求、
  哪个时刻采到的"。
- **反馈四态**：采集中 / 采集成功 / 镜头遮挡·画面不可用 / 采集失败——每次请求
  都能看到明确状态；**失败保持明确状态**，不得在界面上消失或退化成"成功"。
- **最少保留**：图像本体按"最少保留"策略清理（数量 / 时间上限），
  元数据（何时、哪个请求、谁触发）保留可审计。
- **触发与停止条件明确**：触发 = 用户请求（文字/语音）或教学事件；停止 = 沿用第 6 周
  取消语义（采集中可停止关注、迟到图像结果不播报不触发），页面保留文字停止按钮（备用路径）。

## 验收（对应当堂验证）

1. **上次成功图像不得被标为本次采集成功**——每张图必须带本次独立的 request_id 与采集时间；
   任何复用/缓存的旧图都要标注来源（如"回放"），不得冒充本次实拍成功；
2. **采集失败保持明确状态**——失败原因（镜头遮挡 / 画面不可用 / 设备未响应）如实
   呈现并记录，不静默消失。

## 范围

- 图像本体为磁盘文件 + 元数据表（不塞 SQLite BLOB）；最少保留策略可配置，
  默认保留最近 N 张 / 最近 T 小时，超出即清理。
- 演示环境允许使用获授权的历史图像并明确标注"回放"（备用路径）；
  自动化测试仍以真实采集接口路径（含遮挡/失败回执）为准。
- 持续视频流 / 全时录像 / 图像理解（视觉大模型）不在本周范围。

# 第 9 周任务：用视觉事件触发一次主动询问

> 理论 1＋实践 3 学时。前 2 学时讲事件触发、反馈优先级与主动询问条件；
> 后 2 学时做语音、视觉和实体操作协同的中期演示与首轮完整任务测试（含集中排错）。

## 本周问题

画面无法使用时，系统能否主动询问"是否重拍"，并尊重用户选择？

## 本周目标

- **事件触发**：视觉结果（画面不可用 / 低分 / 拒识）成为事件源，
  接入原有任务状态（第 7 周 image 指令、第 8 周推理结果）。
- **反馈优先级与主动询问条件**：只在空闲（无进行中任务、无待领取指令）时才主动问；
  不打断进行中的任务、播报与文字交互。
- **确认、忽略与冷却时间**："重拍"→ 发起新采集；"忽略"→ 本轮/本画面不再问；
  **冷却时间**内不反复打扰（用户拒绝后不反复打扰）；同一画面去重，只问一次。
- **误判能够纠正**：第 8 周纠错入口在本周闭环——用户已纠正的画面不再当作
  "不可用"反复询问。
- **中期可运行原型**：语音、视觉和实体操作协同演示；首轮完整任务测试，
  按**模型、端侧、交互**三类定位问题；含 1 学时集中排错。
- **运行位置说明**：演示中说明模型、设备及服务实际运行位置。

## 验收（对应当堂验证）

1. 误判能够纠正（纠正后不再触发反复询问）；
2. 用户拒绝后不反复打扰（忽略 + 冷却生效）；
3. 演示中说明模型、设备及服务实际运行位置。

## 完成标准（DoD）

- `pytest server` 全绿（既有 + 本周新增用例），第 4–8 周用例不回归；
  `ui_check` / `ui_voice_check` 不回归（只做增量）；
- 完整任务闭环可演示：采集 → 推理 → 画面不可用 → 主动询问"是否重拍" →
  用户确认重拍 / 忽略（冷却）→ 对比两次采集；
- **完整任务测试原始记录**（`docs/week9-test-record.md`）+ **问题归因与修复清单**
  （`docs/week9-attribution.md`，按模型/端侧/交互分类）；
- README 补第 9 周小节与迁移规则（重拍复用 image 指令与第 6 周取消/迟到隔离口径）；
- 确定个人项目期末迁移的一个交互模块及验证任务（记录在 README / 个人项目清单）。

## 范围

- 三课使用同一输入样例和构建版本；提前准备模型失败、采集失败与用户拒绝三类场景。
- 端侧（模型在微控制器上跑）不预设本周必须完成；无实体设备时以
  接口替代定位联调故障，缺项列入补验。
- 主动询问只针对"画面无法使用"这一类事件；不做闲聊式主动打扰。

## 备用路径

联调故障按接口替代定位；在已有真实基线上保留完整任务，缺项列入补验。
